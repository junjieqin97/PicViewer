# PicViewer Project Development Plan

* You are developing a desktop photo preview tool. It supports opening common image formats such as JPG, PNG, and TIFF, and also supports opening RAW files from various cameras.

## Basic Features

* After a photo is opened with this photo preview tool, the tool supports displaying the photo's corresponding `histogram`, `waveform`, and `metadata`.
* When opening a photo, the app reads the embedded ICC profile when available. If no ICC profile is present, the profile cannot be read, or embedded ICC conversion fails, the source image is interpreted with the user-selected fallback image color space. RAW images are decoded by rawpy into ProPhoto RGB and use ProPhoto RGB as their fixed source color space. The Analysis panel shows the current image source color space or fallback reason, provides an `Analysis Sample Precision` selector with `8-bit/channel` and `16-bit/channel (if available)`, provides a `Specify Image Color Space` selector with `sRGB`, `Display P3`, `Adobe RGB (1998)`, `ProPhoto RGB`, startup-loaded system ICC profiles when supported, and `Choose a local ICC...` for ICC fallback cases, provides a `Rendering Intent` selector with the four ICC rendering intents supported by libvips/LittleCMS, and provides a `Display Color Space` selector with the same color space options plus startup-loaded system ICC profiles and `Choose a local ICC...`; `8-bit/channel` is selected by default for analysis, `sRGB` is selected by default for the fallback source selector, `Perceptual` is selected by default for the rendering intent selector, and `sRGB` is selected by default for the display color space selector. On macOS, startup-loaded system ICC profiles are read from `/Library/ColorSync/Profiles` and its first-level subdirectories; on Windows, they are read from `C:\Windows\System32\spool\drivers\color` and its first-level subdirectories; other platforms do not auto-load system ICC profiles. Choosing a local ICC opens a file dialog for `.icc` and `.icm` files, validates the profile through pyvips/libvips, and uses it for the current application session without persisting the path. Valid embedded ICC profiles always take precedence over the specified fallback source color space, and the fallback source selector is disabled when the current image has a valid embedded ICC profile. For RAW images, the fallback source selector is disabled and fixed to `ProPhoto RGB` without changing the user's global fallback selection. Display preview data is generated from ICC-converted display source pixels. Histogram, waveform, hover pixel samples, and fixed color readouts use the selected analysis sample precision. Gamut mapping uses the selected rendering intent for the image-to-display ICC conversion.
* The `histogram` and `waveform` support switching between `luma mode` and `RGB mode`. The default display mode is `luma mode`.
* In `RGB mode`, the `histogram` and `waveform` support switching between displaying all three RGB channels at the same time and displaying only one of the channels.
* The Analysis panel displays the current image hover pixel values above the histogram as four prefixed numeric readouts: `R {value}`, `G {value}`, `B {value}`, and `L {value}`, retaining semantic channel colors as secondary cues. The readouts show the pixel under the mouse pointer while the pointer is over the active analyzed image, and show `R -1`, `G -1`, `B -1`, and `L -1` when no valid sample is available. The `Luma` value uses the same luma definition as the luma histogram. When `Luma` is not `-1`, the histogram shows a black vertical marker at the corresponding luma position.
* The `Tools > Color Readouts` menu supports fixed color readouts. `Add Color Readout` switches the image cursor to a plus-style cursor, and clicking a loaded analyzed image pixel adds a persistent label at that pixel. `Delete Color Readout` switches the image cursor to a minus-style cursor, and clicking a readout label removes that label. `Delete All Readouts` removes all readout labels from the current image only. The sibling `Tools > Color Readouts Type` menu globally selects `RGBL`, `HSB`, `HSL`, or `Lab` for all fixed readout labels in the current application session, with `RGBL` selected by default. Switching the type immediately refreshes existing labels without changing their sampled pixels. RGBL labels display the sampled `R`, `G`, `B`, and `Luma` integer values; HSB and HSL labels display labeled integer hue degrees and percentage values normalized from the active 8-bit or 16-bit analysis precision; Lab labels display integer D65 CIE L\*a\*b\* values as `L n`, `a n`, and `b n` from the same normalized analysis RGB sample. Each label uses a nearly transparent background. RGBL channel values use red, green, and blue text with theme-aware luma text, while HSB, HSL, and Lab values use theme-aware neutral text. Multiple readouts can be attached to one image during the current application session. Readouts are stored per image, are refreshed when analysis data changes, and are not persisted after the image is closed or the application exits.
* `Metadata` can display four types of `metadata`, `General`, `Exif`, `IPTC`, and `TIFF`. The default display type is `General`.
* The left Y-axis of the `waveform` displays `exposure values` from bottom to top (`0`, `20`, `40`, `60`, `80`, and `100`). The `exposure values` `20`, `40`, `60`, and `80` should show `tick marks`. The `exposure values` and `tick marks` are displayed in `yellow`.
* The upper-left and upper-right corners of the `histogram` have `small triangles`. Activating the upper-left triangle displays the `underexposed` areas in the photo, and activating the upper-right triangle displays the `overexposed` areas in the photo. The `underexposed` areas are shown with `green` pseudo color, and the `overexposed` areas are shown with `red` pseudo color.
* The `Pseudo Color` menu supports the `Show Peaking` feature. When enabled, it uses `blue` pseudo color to display focus peaks in the image. `Show Peaking` provides three levels: `High`, `Medium`, and `Low`; `High` is more sensitive and shows more peaks, while `Low` is stricter and shows only the strongest peaks.
* The image display area supports `reference lines`, including three types: `crosshair reference line`, `diagonal reference line`, and `rule-of-thirds grid reference line`. All three reference lines support independent toggles, can be enabled at the same time, and can be displayed as overlays. Reference lines are uniformly drawn in `white` with a `3px` line width over the image preview area.

## Implementation Details

This section documents the current technical implementation of the image loading, image display, and image analysis pipelines. The implementation is intentionally split across UI, controller, application service, domain rules, and infrastructure adapters so that image I/O and analysis remain testable without a Qt event loop.

### Image Loading Pipeline

The application is assembled in `src/pic_viewer/main.py`. `build_services()` creates a shared `ColorProfileConverter`, injects it into `ImageReader`, and then wires `ImageReader`, `ImageAnalyzer`, `MetadataReader`, and the converter into `ImageService`. `main()` also creates an `AnalysisViewService` and passes both services into `MainWindow`, which constructs `MainController`. This keeps the GUI responsible for presentation while `ImageService` coordinates loading, color conversion, analysis, and metadata extraction.

User entry points converge in `MainControllerTabsMixin`. `Open Image`, `Open Folder`, and file drop events all eventually call `_open_image_paths()` or `open_image()`. Folder and drag-and-drop imports are filtered by `filter_supported_image_paths()`, whose suffix policy currently accepts JPG/JPEG, PNG, TIFF/TIF, BMP, WEBP, AVIF, HEIF/HEIC, and common RAW suffixes such as DNG, NEF, CR2, ARW, and RAF. Opening a new image immediately creates an image tab, adds a filmstrip item with a placeholder icon, starts a per-path load session, and launches asynchronous loading.

Background work is handled by `PreviewLoadTask` and `ImageLoadTask` in `src/pic_viewer/ui/workers/image_worker.py`. Both are `QRunnable` objects executed by the controller's `QThreadPool`, whose maximum concurrency is `MAX_IMAGE_LOAD_CONCURRENCY = 8`. `PreviewLoadTask` calls `ImageService.load_preview()` for a lightweight preview payload, while `ImageLoadTask` calls `ImageService.load_and_analyze()` for the full payload and passes the current analysis sample precision. The tasks emit either `finished(object)` or `error(str)` signals, allowing the Qt main thread to update UI state without performing image I/O directly.

The controller guards every asynchronous result with a path session id. `_start_path_session()` increments a per-path counter and records the active session. `_on_preview_loaded()`, `_on_loaded()`, `_on_preview_error()`, and `_on_error()` ignore results whose session no longer matches, which prevents stale worker output from replacing newer state after a retry, close, or color-space reload. The controller also compares the result's display color space, assumed source color space, rendering intent, CMS bit depth, and analysis bit depth against the current global selections before accepting the result. Selecting 16-bit analysis accepts an 8-bit actual analysis result only when the ICC-converted display source is itself 8-bit.

The loading pipeline has two payload levels:

- Preview payload: `ImageService.load_preview()` calls `ImageReader.read_preview_with_profile_and_depth()`, then converts the resulting BGR image to `preview_rgb` through `ImageAnalyzer.build_preview_rgb()`. The controller stores this as `PreviewLoadResult` in `_preview_by_path` and uses it only for incremental UI state such as the filmstrip icon and source color-space status. The main image tab remains in the centered loading state until the full payload is available.
- Full payload: `ImageService.load_and_analyze()` calls `ImageReader.read_with_profile_and_depth()`, passes the converted BGR pixels and selected analysis sample precision into `ImageAnalyzer.analyze()`, reads metadata through `MetadataReader.read()`, builds General metadata such as file name, path, file size, and resolution, and returns `ImageLoadResult`. The controller stores this in `_images_by_path`, removes any preview-only cache entry for that path, refreshes the filmstrip icon from the full analysis preview, updates the right info panel, and finally renders the image tab.

`ImageReader` implements decoder fallback in infrastructure code. It first validates that the path exists and is a file. RAW suffixes are separated into `RAW_IMAGE_SUFFIXES` and, when RAW loading is enabled, are decoded with `rawpy` before OpenCV or Pillow are attempted. RAW preview uses `half_size=True`, full RAW loading uses the full demosaic path, and both call `raw.postprocess(output_bps=16, output_color=rawpy.ColorSpace.ProPhoto)`, so RAW display source data is always ProPhoto RGB at 16-bit/channel. For normal image formats, full loading first tries pyvips to preserve `uchar` or `ushort` precision, then falls back to OpenCV `IMREAD_UNCHANGED`, and finally falls back to Pillow as an 8-bit decoder. All successful decoder outputs are normalized to contiguous BGR `numpy.ndarray` data with dtype `uint8` or `uint16`.

Fast preview loading uses `ImageReader.read_preview_with_profile_and_depth()`. RAW previews still use rawpy 16-bit output. Non-RAW previews try OpenCV reduced-resolution flags first for responsiveness, then pyvips, OpenCV `IMREAD_UNCHANGED`, and Pillow. Every preview is capped by `_resize_if_needed()` using a `max_edge` default of 1920 before color conversion. Full image loading skips the reduced OpenCV flags and lets `ImageAnalyzer` later cap display and analysis sizes.

Color management is part of image loading, not display-only rendering. `ColorProfileConverter.convert_file_bgr_to_display_space_with_depth()` reads embedded ICC bytes with Pillow metadata access for non-RAW images, validates ICC data through pyvips/libvips, and converts decoded RGB pixels from the source profile to the selected display color profile with `icc_transform()`. RAW images provide a ProPhoto RGB source-profile override, so they skip embedded ICC probing and use the ProPhoto RGB profile directly as the input profile. Built-in profiles are supplied by Qt's `QColorSpace` ICC bytes for sRGB, Display P3, Adobe RGB (1998), and ProPhoto RGB, then cached as session-local ICC files because libvips expects profile paths. At startup, `ImageService.load_system_color_profiles()` discovers supported operating-system ICC/ICM profile files, validates them through the same converter path, skips invalid profiles with logs, and passes valid profiles to both Analysis panel color-space selectors. Session-local `.icc` or `.icm` files are loaded through `ImageService.load_local_color_profile()` and cached by a stable key derived from profile bytes and path. Pillow remains available as an image decoder fallback, but Pillow ImageCms is no longer used for CMS conversion.

If a valid embedded ICC profile exists, it takes precedence over the specified fallback source color space. If the embedded ICC profile is missing, invalid, unreadable, or conversion fails, the converter falls back to the controller's selected assumed source color space and returns an `ImageColorProfileInfo` status describing what happened. RAW images return a dedicated decoded RAW status with ProPhoto RGB as the fixed source. The Analysis panel uses that status to show a localized source color-space label, disables the fallback selector when the source has a valid embedded ICC profile, and locks the fallback selector to ProPhoto RGB while a RAW image is active.

Metadata loading is optional and failure-tolerant. `ImageService.warm_up_optional_backends()` asks `MetadataReader` to import `pyexiv2` during startup so the first worker does not pay the native library import cost. `MetadataReader.read()` uses a reentrant lock around `pyexiv2.Image` access, reads Exif and IPTC sections, derives TIFF entries from `Exif.Image.*` and `Exif.Thumbnail.*`, normalizes tag labels and values into sorted `(key, value)` tuples, and returns empty sections if the backend is missing or parsing fails.

Loading errors are converted into user-facing states by `MainControllerLoadingMixin`. Preview failures do not immediately fail the image; if the path is current, the controller displays a status message and falls through to full loading. Full load failures are localized, stored in `_load_error_by_path`, shown inside the tab's `ImageLoadStateWidget`, and mirrored in the metadata/analysis panels. The retry button clears cached preview/full/error state, starts a new session, and restarts both preview and full loads.

### Image Display Pipeline

The display surface is created in `MainWindowUI` and controlled by `MainController`. The main window uses a vertical layout containing the analysis toolbar, a horizontal splitter, and the filmstrip. The splitter contains `tabsImages` on the left and `scrollInfo` with `tabsInfo` on the right. Image tabs and top-level info tabs are `DetachableTabWidget` instances, so image tabs can be detached while remaining synchronized with the controller's active path, filmstrip selection, zoom state, overlays, and info panel updates.

Each image tab is a small state machine. `_build_image_tab_container()` creates a `QStackedWidget` with an `ImageLoadStateWidget` page and an image preview page. The preview page contains a `QScrollArea` named `scrollImage`, whose widget is an `ImageDisplayLabel` named `lblImage`. While full loading is pending, the stack shows the loading state. On success, `_set_tab_pixmap()` sets the pixmap on `lblImage` and switches the stack to the image page. On failure, the stack shows an error state with a retry action.

`ImageDisplayLabel` is the central paint surface for image overlays. It subclasses `QLabel`, lets the base label paint the current pixmap, and then draws reference lines, metadata overlay text, and persistent color readout labels in `paintEvent()`. Reference lines are generated by the pure domain function `build_reference_line_segments()` and are drawn in widget-local coordinates over the logical pixmap rectangle. Metadata overlay text is clipped to the displayed pixmap and limited to three lines. Color readout markers and labels are positioned by mapping analysis-space pixel coordinates to the displayed pixmap rectangle.

Conversion from `numpy` RGB arrays to Qt pixels is centralized in `src/pic_viewer/ui/utils/image_qt.py`. `to_qpixmap()` creates a `QImage` with `Format_RGB888`, tags it with the selected Qt color space when possible, converts it to `QPixmap`, scales it to the target logical size multiplied by the device pixel ratio, keeps aspect ratio, uses smooth transformation, and then sets the pixmap DPR. The same helper is used for the main image tab, filmstrip thumbnails, histogram, and waveform previews.

Main image rendering is handled by `MainControllerAnalysisMixin._set_tab_pixmap()`. It derives the target logical size from the current viewport size and per-path zoom state. Fit-to-window mode uses the viewport as the target size; manual zoom multiplies the viewport size by the stored zoom factor, clamped between `_zoom_min` and `_zoom_max`. The render key includes target size, DPR, pseudo-color flags, focus peaking level, color-space settings, rendering intent, and `id(preview_rgb)`. If the existing pixmap already matches this key and target size, rendering is skipped.

The preview data shown in the image tab is always `ImageAnalysis.preview_rgb` from the accepted full payload, converted into the selected display color space during loading. Before converting to `QPixmap`, `_set_tab_pixmap()` calls `ImageService.build_preview_with_pseudo_color_overlay()` to apply optional underexposed, overexposed, and focus-peaking overlays. This keeps the original analysis payload immutable and makes overlay toggles cheap: the controller only invalidates the tab render key and regenerates the visible pixmap.

Pseudo-color overlays are composited in the domain layer. Exposure warnings use `apply_exposure_overlay()` with luma thresholds of `<= 5` for green underexposure and `>= 250` for red overexposure, blended with alpha `0.65`. Focus peaking uses `apply_focus_peaking_overlay()`, computes luma edge strength with Sobel gradients, and compares against level thresholds: High `32.0`, Medium `72.0`, and Low `128.0`. If both exposure warnings and focus peaking are active, exposure overlays are applied first and focus peaking is applied to the result.

Zoom and panning are pure view concerns. Mouse wheel events on widgets marked `_image_zoom_area` call `_zoom_in()` or `_zoom_out()`. Drag-to-pan is enabled when the image is larger than the scroll area viewport; press stores the global mouse position and current scroll offsets, move updates the scroll bars, and release clears the drag state. A fit-to-window command resets the per-path zoom to `1.0` and marks the path as fit mode.

Filmstrip rendering is managed by `MainControllerFilmstripMixin`. Each image path has a `QListWidgetItem` storing the path in `UserRole`, showing the full file name as text and tooltip. Preview/full load completion calls `_update_filmstrip_icon()`, which converts the RGB preview to a DPR-aware icon pixmap using the current filmstrip icon size. Filmstrip resizing is debounced by a timer; when the pane height changes, the icon side and item size hints are recalculated and existing full-load icons are regenerated.

The Filmstrip pane also contains a lightweight filter toolbar above the thumbnail list. `FilmstripFilterService` keeps filtering rules outside the UI layer and evaluates extension, camera model, and lens model filters with AND semantics. Extension candidates are available immediately from opened paths and are normalized to lowercase suffixes. Camera and lens candidates are populated by low-priority metadata-only background tasks through `ImageService.read_metadata()`, and full image load results refresh the same filter cache when their metadata arrives. Missing or unreadable camera/lens metadata is grouped as `Unknown Camera` or `Unknown Lens`. Applying a filter only hides or shows Filmstrip items; it does not close image tabs, cancel workers, or remove cached image data. If a filter excludes the current image while other images still match, the controller activates the first visible match. If no item matches, the Filmstrip selection is cleared while the current image remains open.

The display pipeline also handles hidden-panel context. When the filmstrip pane is hidden, `_sync_filmstrip_summary()` shows a status-bar summary in the form `Current: {name} ({index}/{total})`, where index and total count only currently visible filtered Filmstrip items; when the filmstrip is visible or no visible image is active, that permanent label is hidden. When the info panel is hidden, the splitter stores the last sizes and collapses the right side; restoring the panel either reuses stored sizes or recomputes default sizes from the window width.

### Image Analysis Pipeline

The analysis pipeline begins after full image decoding and color conversion. `ImageService.load_and_analyze()` passes the display-space BGR array to `ImageAnalyzer.analyze()`. This means histogram, waveform, pixel sampling, fixed color readouts, metadata overlay resolution, and the displayed preview all operate on the same selected display color space. The returned `ImageAnalysis` DTO stores both pre-rendered analysis images and the source data needed for later re-rendering.

`ImageAnalyzer.analyze()` first records the original source size as `(height, width)`. It then builds `analysis_bgr`, capped by `DEFAULT_MAX_ANALYSIS_EDGE = 4096`, so large images remain responsive while analysis and pixel sampling stay spatially consistent. It converts that to RGB and builds `preview_rgb`, capped by `DEFAULT_MAX_DISPLAY_EDGE = 4096`, for main display and thumbnails. The full-resolution decoded array is not kept in controller state.

The analyzer precomputes the default analysis views at load time:

- `histogram_luma`, `histogram_rgb`, `histogram_r`, `histogram_g`, and `histogram_b`.
- `waveform_luma`, `waveform_rgb`, `waveform_r`, `waveform_g`, and `waveform_b`.

These precomputed images are stored in `ImageAnalysis` and allow the UI to switch between Luma/RGB modes or individual RGB channels without reloading the file. `AnalysisViewService.build_view()` selects the appropriate pair based on `AnalysisViewSettings(mode, channel)`. When the UI needs DPR-aware or different-size renders, `ImageService.render_analysis_view()` re-renders from `analysis.analysis_bgr`; if rendering fails or the requested size is invalid, it falls back to the precomputed images.

Histogram rendering is implemented by `ImageAnalyzer.render_histogram_channels()` and `render_histogram_luma()`. Channel histograms use OpenCV channel indices in BGR order (`0` blue, `1` green, `2` red) but return RGB plot images for Qt display. Luma histograms use `cv2.cvtColor(bgr, cv2.COLOR_BGR2GRAY)`, which is also the luma definition used by hover pixel sampling. Each histogram is drawn on a fixed gray background with OpenCV anti-aliased line drawing. The controller displays it in `HistogramClippingLabel`, which additionally draws under/overexposure triangles and a vertical black luma marker for the current hover sample.

Waveform rendering is implemented by `ImageAnalyzer.render_waveform_channels()` and `render_waveform_luma()`. The source is resized to the plot width while preserving aspect ratio. For each x-column, pixel values are mapped to y positions using `height - 1 - value * (height - 1) // 255`, then accumulated with `np.add.at()`. The accumulated density is normalized with percentile clipping (`99.5`), logarithmic gain (`6.0`), gamma (`0.7`), and optional Gaussian blur (`sigma = 0.8`) before being converted to an RGB image.

The waveform exposure axis is also part of the domain renderer. `_apply_waveform_axis()` draws a yellow vertical axis, yellow labels for `0`, `20`, `40`, `60`, `80`, and `100`, and yellow tick lines for `20`, `40`, `60`, and `80`. With the current configuration, tick length `0` means each tick spans from the y-axis to the right edge of the waveform image. Geometry is scaled by device pixel ratio so text thickness and label placement remain consistent on high-DPI displays.

The Analysis panel is refreshed through `MainControllerAnalysisMixin.update_info_for_image()`. Empty charts prompt the user to open an image; loading charts show concise generation messages; failed charts show `Histogram unavailable` and `Waveform unavailable`, with detailed errors and retry available on the image page. All chart state text is localized, centered, and word-wrapped within the existing fixed chart sizes. Non-loaded states clear previous chart pixmaps, pixel samples, and the luma marker. For loaded paths the panel synchronizes the source color-space label, metadata tables, pixel sample state, fixed color readouts, and analysis pixmaps. The render key contains histogram size, waveform size, DPR, mode, channel, display color space, assumed source color space, and rendering intent; this prevents unnecessary redraws while ensuring changed color settings or view settings invalidate the cached pixmaps.

Hover pixel sampling is handled in `MainControllerInteractionMixin._handle_pixel_sample_event()`. Mouse positions are resolved to `ImageDisplayLabel`, then mapped from label-local coordinates to analysis-space `(x, y)` with `ImageDisplayLabel.image_pixel_position_at()`. The controller samples `analysis_bgr` using `sample_analysis_pixel()`, updates the `R`, `G`, `B`, and `Luma` labels above the histogram, and passes the luma value to `HistogramClippingLabel.set_luma_marker_value()`. Leaving the image or moving outside the displayed pixmap resets the readouts to `R -1`, `G -1`, `B -1`, and `L -1`.

Fixed color readouts reuse the same analysis-space sampling path. Add mode maps the click to `analysis_bgr`, samples RGB and luma, stores a `ColorReadout` with a session-local id and the actual analysis bit depth in `_color_readouts_by_path`, and applies the readout list to every label that displays the same image path. The global `ColorReadoutType` controls whether labels format the stored sample as RGBL, HSB, HSL, or Lab; HSB/HSL and D65 Lab conversions normalize using the recorded channel bit depth, and changing the type repaints all attached and detached image labels without resampling. Delete mode checks whether the click intersects a marker or label rectangle and removes only that readout. When analysis data changes, `_refresh_color_readouts_for_path()` clamps stored coordinates to the new analysis dimensions and resamples values and bit depth.

Metadata analysis is represented as structured DTO data rather than UI table state. `ImageService.load_and_analyze()` combines pyexiv2-derived Exif/IPTC/TIFF sections with General metadata derived from file system state and `ImageAnalysis.source_size`. `MainControllerMetadataMixin` renders those sections into four `QTableWidget` instances and uses `build_metadata_overlay_lines()` to derive the optional three-line overlay: camera/lens, exposure settings, and resolution. Missing fields are omitted instead of shown as placeholders.

Overall, the analysis pipeline's single source of truth is the accepted `ImageLoadResult` stored in `_images_by_path`. UI widgets never own analysis data; they render selected views, overlays, and labels derived from that DTO. Reloading color settings clears the affected caches, starts new sessions, and regenerates both preview and full analysis data so display and analysis remain consistent.

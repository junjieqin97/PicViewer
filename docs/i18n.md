# PicViewer Internationalization Conventions

## Goals

- Initially support `zh_CN` and `en`.
- Use `.ts/.qm + QTranslator`.
- Runtime language switching is not supported; the language is determined at startup.

## Language Selection Rules

Priority is as follows:

1. Environment variable `PICVIEWER_LANG`
2. System language `QLocale.system().name()`
3. Default `en`

Supported mappings:

- `zh` / `zh_CN` / `zh-CN` -> `zh_CN`
- `en` / `en_US` / `en-GB` -> `en`
- Other values -> treated as unset

## Text Extraction and Translation Files

- Translation source directory: `src/pic_viewer/ui/resources/i18n`
- Translation files:
  - `picviewer_zh_CN.ts`
  - `picviewer_en.ts`
- The Qt source language is English; `picviewer_zh_CN.ts` provides Chinese translations, and `picviewer_en.ts` keeps the same English text as the source.

Update TS:

```bash
scripts/i18n/update_ts.sh
```

Generate QM:

```bash
scripts/i18n/build_qm.sh
```

## Repository and Release Conventions

- Only `.ts` files are committed to the repository.
- CI/packaging generates `.qm` files and includes them in the release artifacts.
- If no Chinese `.qm` is available when running locally from source, the application automatically falls back to English and does not block development.

## New Copy Rules

- All user-visible text must go through translation functions and must not be hardcoded directly in UI display paths.
- The UI layer uniformly uses `_tr(...)`.
- The service layer and domain layer must remain free of Qt dependencies; fixed prompt text from the backend is mapped to localized text in the Controller layer.

## Pre-Release Checks

1. Run `scripts/i18n/update_ts.sh` and confirm that no text is missing.
2. Run `scripts/i18n/build_qm.sh` and confirm that `picviewer_zh_CN.qm` and `picviewer_en.qm` can be generated.
3. Start with `PICVIEWER_LANG=en` to verify the English source text; start with `PICVIEWER_LANG=zh_CN` to verify that menus, labels, dialogs, the status bar, and metadata empty states are all in Chinese.
